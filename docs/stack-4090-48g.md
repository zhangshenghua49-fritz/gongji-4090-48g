## 0. 我先认错的地方

旧版把 Wan2.2-A14B 与 LTX-2.3 当主力，理由是「Wan 2.5/2.6/2.7 无开源权重」——**这条本身没错**（实测
`Wan-AI/Wan2.5`、`Wan-AI/Wan2.6` 均返回 401，确无权重）。错在结论：**我把「Wan 没有新权重」误当成
「没有更新的开源视频模型」**。实际当下最强的开源音视频模型来自 MiniMax，不来自 Wan。

实测佐证（HF `pipeline_tag=text-to-video` 按下载量排序，前 60 条）：

## 1. 视频层：MiniMax-H3 是主力

### 1.1 官方规格（摘自模型卡，不是二手转述）

| 项 | 规格 |
|---|---|
| 定位 | omni-modal 生成系统，text/image/video/audio 统一上下文 |
| 输出 | 视频 + **原生 32 kHz 立体声**（对白/音效/音乐一次出） |
| 时长 | **4–15 秒**，24 FPS |
| 分辨率 | 短边默认 **768**；1 MP 附近训练（16:9 → 1344×768） |
| 2K | 需 **H3-Regenerate-2K** 二次生成，不是一次直出 |
| 变体 | **FL2VA**（首尾帧：0/1/2 图 → T2V / I2V / 首尾帧）；**Ref2VA**（≤9 图、≤3 视频、≤3 音频，共 ≤12 文件） |
| 语言 | 对白稳定支持 11 种：阿/中/英/法/德/意/日/韩/葡/俄/西 |
| text encoder | **Qwen3-VL-32B 全量权重，取第 50 层 hidden states** |
| license | `minimax-h3-community-license-agreement`（非标准开源） |

**三个必须知道的坑**：

1. **H3-Context-IR 未开源**。官方明确：它是托管的多阶段预处理系统，「不包含在本次开源发布中」，
   只提供 API 复现。→ 本地跑要自己写提示词预处理，或调 API。
2. **稀疏推理没给**。官方：「训练和推理原生支持 sparse attention」，但「初始开源版本仅提供
   full attention 推理，稀疏实现将在后续更新中发布」。→ 现在只能在 ComfyUI 里用 Sage / FastH3 补。
3. **商用要买授权**。ComfyUI 官方文档明说：本地生成的输出若要商用，需 MiniMax 商业许可，
   经 Comfy 购买（**唯一官方 reseller**）。

### 1.3 48G 显存账：哪一套能装下

| 组合 | 合计 | 判定 |
|---|---|---|
| pruned_int8 (20.97) + text int8 (27.14) + vae int8 (2.81) + audio (0.61) | **51.53 GB** | ❌ 装不下 |
| pruned_int8 (20.97) + text **nvfp4** (15.69) + vae int8 (2.81) + audio (0.61) | **40.08 GB** | ✅ **推荐**，余 ~8 GB |
| 上者 + turbo 8step LoRA (1.96) | **42.04 GB** | ✅ 含加速 LoRA 仍够（768p 实跑 32–36 GB） |
| pruned_w6a8 (15.98) + nvfp4 (15.69) + vae int8 (2.81) + audio (0.61) | **35.09 GB** | ✅ 最宽裕，给长片留余量 |
| pruned_w6a8 + nvfp4 + turbo | **37.05 GB** | ✅ 批量出草稿首选 |
| 上者 + ControlNet Union int8 (4.53) | **41.58 GB** | ⚠️ 紧，但可跑（R2V/ControlNet 4 步） |
| pruned_bf16 (40.23) + nvfp4 (15.69) | 55.9 GB | ❌ |
| full bf16 (66.28) + 任何 | ≥66 GB | ❌ |

**裁决：默认 `pruned_int8_convrot` + `nvfp4_awq` text encoder + `int8` video VAE + `fp32` audio VAE
+ `turbo 8step` LoRA = 42.04 GB。** 想同时挂 ControlNet Union 时换 `pruned_w6a8`（37.05 → 41.58 GB）。

> **为什么平台镜像只报 27.8 GiB**：`docs/platform-preset-services.md` 原话是「int8 模型 ~20G +
> 文本编码器 nvfp4 ~15G 走 CPU offload」——TE 不常驻显存。全常驻才需要上表的 42 GB。
> 两种口径都对，取决于你把 TE 放哪。

### 1.4 出片参数（官方模板口径，直接用）

| 参数 | 值 |
|---|---|
| 采样器 | `res_multistep` + `simple` |
| shift | `shift=12` / `audio_shift=3`（模型内置；FastH3 用 `shift_video=10`） |
| 步数（无 turbo） | 20 |
| 步数（turbo，T2V/I2V） | 8 |
| 步数（turbo，R2V/Multiframe/ControlNet） | 4 |
| **语音/音色需要的步数** | **≥12**（官方原话：8 步下「audio is often the weak link」） |
| 帧网格 | `17k+5` @24fps（124 帧 = 5 s） |
| 模板默认分辨率 | 0.4 MP（864×480） |
| 16:9 原生甜点 | **0.98 MP ≈ 1344×768** |
| 禁用 | **1.0 MP（1376×768 超出 768×1344 上限）** |

长片靠 I2V continuation 链式接（每段首帧接上段末帧），官方警告误差累积、人脸最先掉细节，
建议 `H3-Anti-Burn-LoRA` 从第二段起挂 `strength_model≈0.5`。

### 1.5 版本门槛

| 能力 | 需要 ComfyUI |
|---|---|
| T2V / I2V / R2V 基础模板 | **0.30.0+** |
| Multiframe Reference | 0.34.0+ |
| Fun ControlNet Union / 稀疏注意力 | 0.35.0+ |
| FastH3 | 0.36.0+ |
| `pruned_w6a8` 检查点 | **0.38.0+** |

→ 镜像里必须装 **ComfyUI 0.38.0 以上（或 nightly）**，这是硬门槛。
另：`int8_convrot` 检查点**不能配 Comfy Kitchen attention 后端**，要么换 bf16 检查点，要么别用该后端。

注意文件名里的 `comfy-int8-convrot` —— 官方直接按 ComfyUI 命名规则发布，**不用额外重打包**。

### H3 vs LTX-2.5 该怎么分工

第三方实测（[kocpc，2026-09-13](https://en.kocpc.com.tw/archives/25429)）结论：
**步数给足时 H3 画质能超过 LTX-2.5，但默认步数下 H3 表现不稳定。**

| 场景 | 选谁 | 理由 |
|---|---|---|
| 需要同期声/对白/音效 | **H3** | 原生 32 kHz 立体声，一次出 |
| 多镜头叙事、镜头衔接 | **LTX-2.5** | 原生 multi-shot，H3 要把多镜写进一个 prompt |
| 出片稳、少调试 | LTX-2.5 distilled 8 步 | H3 默认步数不稳 |
| 画质上限（肯堆步数） | **H3**（20→50 步） | 官方：高频细节到 ~50 步还在改善 |
| 商用 | **LTX-2.5** | LTX-2.x Community：ARR < $10M 免费商用；H3 需买 Comfy 授权 |

→ 两个都装。不冲突：合计权重 ≤ 76 GB，走数据盘。

## 3. 图像层：Z-Image-Turbo 主，Qwen-Image-2.1 补

| 模型 | 参数量 | license | 实测体积（bf16 全量） | 定位 |
|---|---|---|---|---|
| **Tongyi-MAI/Z-Image-Turbo** | **6B** | **Apache-2.0** | 30.64 GB（transformer 22.93 + text_encoder 7.40 + 余） | 8 步快出、商用无忧、独立 T2I 榜 **941 Elo** |
| **Qwen/Qwen-Image-2.1** | **7B**（32 层 Single-Stream DiT） | **Qwen Research License**（研究协议） | 30.86 GB（transformer 13.25 + text_encoder 18.28 + vae 1.26） | 编辑强、RGBA 原生透明、≤10 参考图 |
| Qwen-Image-2.1 FP8（社区 `unsloth`） | — | 同上 | transformer **6.63 GB** + text_encoder FP8 **8.75 GB** | 48G 上最省的 Qwen 路线 |

**关键判断**：Qwen-Image-2.1 是 **Qwen Research License**（模型卡 `license: other / license_name: qwen-research`），
**不是** Apache-2.0。做视频要发平台/变现的话，主力出图用 **Z-Image-Turbo**，Qwen 只做内部编辑/透明素材。

Qwen-Image-2.1 的独特价值（模型卡原文）：
- 原生 RGBA 透明生成 + 透明层编辑 + 从照片抠主体
- 最多 **10 张参考图**，可圈选/涂画/独立 mask 做局部编辑
- 人物与产品的身份保持
- 2048×2048 默认，40 步去噪

Z-Image-Turbo 用 8 步（Turbo 蒸馏），比 Qwen 默认 40 步快一个量级 → **批量试镜、分镜草图**用它。

### Wan2.2 还留不留

留一个 **`wan2.2_ti2v_5B_fp16.safetensors`（10.0 GB）** 作极轻量草稿，
以及 `wan2.2_s2v_14B_fp8_scaled` 做口型对轨（H3 的 Ref2VA 音频参考是「音色/氛围」参考，
不是逐帧口型对齐；真要对口型还是 S2V / InfiniteTalk 更直接）。
其余 Wan2.2 14B 双专家（约 45 GB/对）**不装**——被 H3 全面替代，白占盘。

### 因幡巡怎么办

见 `voice-inaba-meguru.md`。结论一句话：**成品 VITS 权重拿得到（Moe TTS `model.pth` 454 MiB，
speaker sid=1 就是因幡めぐる），但那套是 2022 年 VITS，做短句够、做长旁白机器味重。**
要质感就 GPT-SoVITS 微调；要省事就先用 Qwen3-TTS 日语音色顶上。

## 5. 显存常驻规划（一卡跑全管线）

4090 48G 不能同时常驻 H3 + LTX + 图像 + TTS。用「**按需启停 + 显存回收**」：

| 阶段 | 常驻 | 峰值 |
|---|---|---|
| 出图 / 分镜 | Z-Image-Turbo FP8（~8 GB）+ Qwen3-TTS（~4 GB） | **12 GB** |
| H3 出镜头 | H3 pruned_int8 + nvfp4 TE（34 GB）+ TTS 卸掉 | **39 GB** |
| LTX-2.5 出镜头 | LTX int8（34.4 GB） | **36 GB** |
| 口型对轨 | Wan2.2-S2V fp8（22.8 GB） | **23 GB** |
| 混流/字幕/封装 | ffmpeg（CPU） | 0 |

**不要指望「全部常驻一次跑完」**，48G 装不下两个视频大模型同时驻留。
`boot.sh` 因此设计成**一次只起一个重模型**，切档用 `switch.sh`。

## 6. 磁盘账（修正版）

原版算 86.8 GB。按新选型重算：

| 层 | 内容 | 体积 |
|---|---|---|
| **镜像层（系统盘）** | ComfyUI 0.38+ / 15 个节点 / 4 套 venv / 全部代码 | **≈ 9 GB** |
| 镜像层可选塞入 | Z-Image-Turbo FP8 + Qwen3-TTS + H3 turbo LoRA | +12 GB → 21 GB |
| **数据层（共享卷）** | H3 全套 39 GB + LTX-2.5 全套 36 GB + Wan 草稿 10 GB + Qwen-Image 15 GB | **≈ 100 GB** |
| 数据层再加 | 因幡巡 VITS 三套 0.8 GB + GPT-SoVITS 预训练 2 GB + 语料/训练产出 | +10 GB |

→ **系统盘 80 GB 上限不变，所以仍然必须双层**：镜像只放环境 + 一套「开机即能出草稿」的最小权重，
大权重全走共享存储卷挂载到 `/root/data/models`。
